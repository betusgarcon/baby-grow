二、优化策略总览

针对上述问题，制定了 9 大优化方向，确保导出代码能够被 AI 模型准确理解并还原。

01 修复无效类名
移除所有 size- 不完整类名，替换为 flex-1 或直接删除
02 统一颜色体系
将 stone/slate/zinc/neutral 四套色系统一为 ink / surface / brand 三组语义 Token
03 移除字体硬编码
删除所有 font-['...']，统一在 tailwind.config.ts 全局配置
04 统一圆角
rounded-[32px] → rounded-card，rounded-[48px] → rounded-card-lg
05 统一阴影
自定义 shadow-card / shadow-card-lg / shadow-button / shadow-float
06 outline → border
所有 outline outline-1 替换为标准 border 属性
07 Chart 组件预留
用注释 {/* === CHART: Type === */} 标记，保留容器尺寸，移除内部硬编码 div
08 移除绝对定位
底部导航从 absolute top-[xxx] 改为 flex 流最后元素或 fixed bottom-0
09 公共组件提取
Header / CategoryTabBar / SegmentedControl / BottomNav 等标记为独立组件

五、Figma 中创建与导出 Token 指南

以下步骤详细说明如何在 Figma 中创建上述设计 Token，以及如何将它们集成到 Taro 项目中。

5.1 在 Figma 中创建 Color Styles

打开 Figma 文件的 Local Styles 面板
在右侧面板点击 Paint Styles（填充样式）区域，点击 + 按钮创建新颜色样式。按 Token 分组创建：ink/default、ink/muted、ink/subtle、surface/default、surface/card 等，使用 / 分隔可自动创建文件夹层级。
为每个 Token 设置颜色值
按照 Token 清单中的 Hex 值逐一创建。例如 ink/default 设置为 #1C1917，surface/default 设置为 #FAFAF9。创建时添加描述说明用途，如"主文字：标题、正文主体"。
批量替换现有图层颜色
选中所有使用 stone-900 的图层 → 在 Fill 面板点击样式图标 → 选择 ink/default。使用 Figma 的 Find & Replace 插件可以加速这个过程。特别需要统一：stone-600 / slate-600 / zinc-700 → ink/muted；zinc-500 / neutral-500 → ink/subtle。

5.2 在 Figma 中创建 Text Styles

创建语义化文字样式
在 Text Styles 面板创建以下样式：display/title（24px/700/32px行高）、heading/card（16px/700/20px行高）、body/default（16px/400/24px行高）、caption/label（12px/700/16px行高）、caption/meta（10px/400/10px行高）。统一使用 "Plus Jakarta Sans" 字体，不再单独指定 PingFang SC 或 Nunito Sans。
批量应用到文本图层
选中同类文本（如所有卡片标题）→ 应用 heading/card 样式。这样在 Figma to Code 导出时，插件会输出一致的类名。

5.3 在 Figma 中创建 Effect Styles

创建阴影样式
在 Effect Styles 面板创建：shadow/card（Drop Shadow, 0 4 30 0 rgba(0,0,0,0.04)）、shadow/card-lg（0 30 60 -15 rgba(0,0,0,0.04)）、shadow/button（0 1 2 0 rgba(0,0,0,0.05)）、shadow/float（0 4 6 -4 rgba(0,0,0,0.10)）。
批量应用到卡片图层
选中所有标准卡片 → 在 Effects 面板应用 shadow/card 样式。替换所有手动设置的阴影值。

5.4 从 Figma 导出 Token 到项目

有三种方式将 Figma 中的 Token 同步到代码项目：

方式 A：使用 Figma Tokens 插件（推荐）

安装 Figma Tokens 插件
在 Figma Community 搜索 "Tokens" 或 "Figma Tokens Studio"，安装插件。该插件支持将 Figma 中的 Styles 导出为 JSON 格式的 Token 文件。
导出 Token JSON
在插件面板点击 Export → 选择 JSON 格式 → 下载 tokens.json 文件。文件结构包含 color、borderRadius、boxShadow、typography 等分类。
使用 Style Dictionary 转换
在项目根目录安装 Style Dictionary：npm install -D style-dictionary。创建 config.json 配置文件，将 tokens.json 转换为 tailwind.config.ts 中可用的格式。运行 npx style-dictionary build 生成最终配置。
放置到项目中
生成的 tailwind.config.ts 放在项目根目录，覆盖原有配置。Token JSON 原始文件可放在 design/tokens.json 作为设计源文件归档。

方式 B：手动复制（适合快速启动）

直接使用已生成的配置文件
本报告已附带生成好的 tailwind.config.ts 文件，直接复制到项目根目录即可使用。文件位于 /workspace/optimized-pages/tailwind.config.ts。
确认 Tailwind 依赖版本
确保项目使用 Tailwind CSS v3.0+。如果使用 Taro 的 Tailwind 插件，确认 config.path 指向正确的配置文件位置。

方式 C：使用 Figma REST API（适合 CI/CD 自动化）

获取 Figma API Token
在 Figma Settings → Account → Personal Access Tokens 创建 API Token。记录 File Key（从 Figma 文件 URL 获取）。
调用 Styles API
请求 GET https://api.figma.com/v1/files/:file_key/styles，返回所有 Styles 的定义。编写脚本解析返回值并生成 tailwind.config.ts。
集成到 CI/CD
在 GitHub Actions 中添加步骤，每次设计文件更新后自动拉取最新 Token 并更新配置文件。放在 .github/workflows/sync-tokens.yml。
推荐方案

对于当前阶段，建议使用 方式 B（手动复制）快速启动。将附带的 tailwind.config.ts 复制到项目根目录，在 Figma 中按上述步骤创建 Styles 以保持设计端同步。待团队协作成熟后再升级到方式 A 或 C。

六、Trae 中固化配置规则指南

将设计 Token 和 CSS 优化规范固化到 Trae IDE 中，确保 AI 模型在每次生成代码时都自动遵循这些规则。以下是具体步骤：

6.1 创建项目规则文件

在项目根目录创建 project-rules.md
将附带的 project-rules.md 文件复制到项目根目录。Trae 的 AI 模型会自动读取项目根目录下的规则文件，作为代码生成的上下文约束。
配置 Trae 的上下文引用
在 Trae 的设置中（Settings → AI → Context），添加 project-rules.md 和 tailwind.config.ts 为始终加载的上下文文件。这样 AI 模型在每次对话中都能获取到最新的 Token 定义和使用规范。
在对话中主动引用规则
在每次开始新页面开发时，在 prompt 中添加引导语：请参考 project-rules.md 中的设计 Token 规范，使用 tailwind.config.ts 中定义的语义化类名，chart 区域使用组件占位注释标记。这样即使 AI 模型遗漏了自动加载，也能通过显式引用确保规范被执行。

6.2 配置 Trae 的 Memory 功能

添加持久化记忆
在 Trae 的 Memory 面板中添加以下记忆条目：
- "本项目使用 Taro + TypeScript + Tailwind CSS，设计 Token 定义在 tailwind.config.ts"
- "颜色必须使用语义化 Token：text-ink / text-ink-muted / text-ink-subtle，禁止使用 stone-600 等原始色名"
- "chart 区域必须用 {/* === CHART: Type === */} 注释标记，保留容器尺寸"
- "公共组件（Header, CategoryTabBar, SegmentedControl, BottomNav）必须提取为独立组件"
设置 Token 节省策略
在 Memory 中添加：生成代码时不需要解释每个类名的含义，直接输出代码。变更说明使用表格格式，放在代码块之后。 这样可以减少输出 Token，降低使用成本。

6.3 在对话模板中使用规则

创建一个可复用的对话模板（Prompt Template），每次开发新页面时使用：

/* 对话模板：新页面开发 */

1. 参照 project-rules.md 中的设计 Token 规范
2. 使用 tailwind.config.ts 中定义的语义化类名
3. chart 区域使用 {/* === CHART: Type === */} 注释标记
4. 公共组件提取为独立文件（Header, CategoryTabBar 等）
5. 使用 Taro 组件：<View> 替代 div，<Text> 替代 span

7. 变更说明用表格格式输出

6.4 验证与迭代

生成代码后自检
让 AI 模型在生成代码后执行自检：搜索是否有 stone-、slate-、zinc-、neutral- 等禁用色名残留；搜索是否有 font-[' 硬编码字体；搜索是否有 outline outline- 未替换的属性。
定期更新规则文件
当设计 Token 体系扩展（如新增暗色模式、新增品牌色变体）时，同步更新 project-rules.md 和 tailwind.config.ts，确保规则与配置保持同步。

7.4 图表组件

图表组件实现建议

所有图表组件建议使用 ECharts（Taro 版本：taro-echarts 或 @bicosto/echarts）实现。每个图表组件应接收数据 props，内部处理渲染逻辑，不暴露样式细节给调用方。

组件名使用页面ECharts 类型关键 Props
<LineChart /> Growth line + markLine data, xField, yField, standardRange
<DonutChart /> Growth, Diet Month pie (doughnut) data: {label, value, color}[], centerLabel, centerValue
<BarChart /> Diet Week bar data: {day, value}[], standardRange, highlightIndex
<RadialRingChart /> Sleep Daily gauge / pie (custom) segments: {start, end, color}[], centerLabel, centerValue, timeLabels
<StackedBarChart /> Sleep Monthly bar (stacked, horizontal) rows: {label, segments: {width, type}[]}[], segmentColors: {night, nap}
<CalendarGrid /> Mood custom (grid) month, events: {date, mood, intensity}[], onDateClick

组件抽取优先级建议

建议按以下优先级抽取组件：第一批（Header、CategoryTabBar、BottomNav、AINarrativeCard）——全页面复用，抽取后立即减少 50%+ 重复代码；第二批（SegmentedControl、TagPill、PageContainer）——多页面复用；第三批（KpiMetric、SleepLogItem、MoodSelector）——单页面专用，可在该页面开发时一并抽取。
